# Runtime HTTP contract

The HTTP surface the BuildY app (`apps/chat-web`) calls on its runtime: `/runtime/healthz`, `/runtime/v1/status`, `/runtime/v1/run`, `/runtime/v1/media` (generate, result, asset, encode), and on the desktop host `/runtime/v1/xai/chat/completions`, the forward the webview's agent loop calls (`cases/xai-forward.json`). One set of cases, every host must pass them ([ADR 0065](../../.project/adr/0065-runtime-http-contract.md)).

- `cases/*.json`: hand-written cases. A case is one request, the provider and image-host exchanges it causes (`upstream`, any order, each used once), and the expected answer (status, a subset of the JSON, headers, bytes, words it must not contain). `surfaces` names the hosts it binds (`node`, `vercel`, `desktop`; default all three).
- `constants.json` and `pictures/`: generated by `npm run contract:runtime` from the sources (never edited by hand). `npm test` fails when they are out of date.
- `capabilities.schema.json`: the optional `capabilities` of `/v1/status` (absent on the web hosts, sent by the desktop host).

Macros inside a case: `$KEY` (the test key; the answer never contains it, checked on every case), `$CONTRACT` (the contract fingerprint), `$CANDIDATE` (the default chat model), `$IMAGE_MODEL`, `{ "$repeat": [text, count] }`, in requests, expectations and upstream replies alike (a reply can echo `$KEY` to prove the host never repeats it). Matchers in `expect.json`: `$absent`, `$boolean`, `$prefix:<text>`. Bodies: `json`, `text`, or `bytes` (`hex`, `size` + `fill`, or `picture` from `pictures/`). Upstream URLs that start with `/` are relative to the xAI base URL.

Runners: `scripts/m4-api-tests/runtime-http-contract.test.ts` here (node and vercel surfaces, in process); the desktop host [`buildytech/buildychat-desktop`](https://github.com/buildytech/buildychat-desktop) embeds this directory from its pinned `third_party/chat` submodule and runs the `desktop` surface with Go `httptest`. Encoded WebP bytes are never compared, only sizes, qualities and the grade.
