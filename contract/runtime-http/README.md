# Runtime HTTP contract

The HTTP surface the BuildY app (`apps/chat-web`) calls on its runtime: `/runtime/healthz`, `/runtime/v1/status`, `/runtime/v1/run`, `/runtime/v1/media` (generate, result, asset, encode), `/runtime/v1/design` (Design mode, web hosts only), and on the desktop host `/runtime/v1/xai/chat/completions`, the forward the webview's agent loop calls (`cases/xai-forward.json`), and its OpenRouter sign-in, forward and draws (`cases/openrouter-auth.json`, `cases/openrouter-forward.json`, `cases/media-openrouter.json`, [ADR 0067](../../.project/adr/0067-openrouter-desktop-sign-in.md)). One set of cases, every host must pass them ([ADR 0065](../../.project/adr/0065-runtime-http-contract.md)).

- `cases/*.json`: hand-written cases. A case is one request, the provider and image-host exchanges it causes (`upstream`, any order, each used once), and the expected answer (status, a subset of the JSON, headers, bytes, words it must not contain). `surfaces` names the hosts it binds (`node`, `vercel`, `desktop`; default all three).
- `constants.json` and `pictures/`: generated by `npm run contract:runtime` from the sources (never edited by hand). `npm test` fails when they are out of date.
- `encode/`: generated goldens, this runtime's (sharp) WebP sizes of some pictures with the default grade; another encoder must match each size's width, height, quality and sharpen exactly and stay within `index.json` `tolerance` (bytes ratio, SSIM). Never compared byte for byte.
- `capabilities.schema.json`: the optional `capabilities` of `/v1/status` (absent on the web hosts, sent by the desktop host).
- `host.schema.json`: the optional `host` of `/v1/status` (the desktop host's kind, stamped version, os and arch; absent on the web hosts, so the app knows it runs in a browser). `constants.json` `host` holds the version shape and the version of an unstamped build.
- `providers.schema.json` and `provider-settings.schema.json` (ADR 0068): the desktop's `providers` of `/v1/status` (one entry per provider: state, key presence, roles, served models) and the approved-model lists of `/runtime/v1/settings/providers`. `cases/media-provider.json` (media `provider`/`model`, refusals, `provider_limit`), `cases/provider-settings.json`, `cases/keys-xai.json` (the xAI key typed in Settings). `constants.json` `providers` and `openrouter.mediaEnabled` come from `packages/agent-manifests/src/roles.ts`. Desktop runner fields: `env.openrouterMedia` (OpenRouter pictures switched on), `env.limited` (providers seen at a limit), `env.approved` (saved lists), `expect.limitedAfter`, `expect.approvedAfter`, `expect.xaiKeyAfter`.
- `provider.schema.json`: the optional `provider` of `/v1/status` (desktop only: `openrouter` when signed in with OpenRouter, else `xai`; signed in; sign-in pending). `capabilities.signIn` lists the sign-ins the host offers. `constants.json` `openrouter` holds the base and auth URLs, the callback shape, the allowed chat models, the image model and the discovery paths (from `packages/provider-xai/src/openrouter.ts`).

Macros inside a case: `$FILE:<picture>` (desktop: the store address `/runtime/v1/files/<sha256>.<ext>` of a file of `pictures/`; a case's `store` lists the pictures it starts with; `cases/export.json` adds `env.save`, `exports` and `expect.saved`, see its `$comment`), `$KEY` (the test key; the answer never contains it, checked on every case), `$CONTRACT` (the contract fingerprint), `$CANDIDATE` (the default chat model), `$IMAGE_MODEL`, `{ "$repeat": [text, count] }`, in requests, expectations and upstream replies alike (a reply can echo `$KEY` to prove the host never repeats it). Matchers in `expect.json`: `$absent`, `$boolean`, `$prefix:<text>`, `$match:<regex>` (a string the pattern finds; RE2-compatible patterns only, the Go runner uses `regexp`). Bodies: `json`, `text`, or `bytes` (`hex`, `size` + `fill`, or `picture` from `pictures/`). Upstream URLs that start with `/` are relative to the xAI base URL, `$OPENROUTER/…` to the OpenRouter base URL. Desktop-only fields of the OpenRouter cases: `$ORKEY` (the test OpenRouter key, never answered either), `$VERIFIER` (the PKCE verifier of a seeded sign-in), `$B64:<picture>` (the base64 of a file of `pictures/`, in replies), `env.openrouter` (an OpenRouter key in the keychain), `env.pendingSignIn` (`state`, `verifier`, `expired`), `request.listener: "callback"` (the request goes to the loopback callback listener, not the app origin), `match.auth: "openrouter"` (the OpenRouter key as bearer), `match.headers` (request headers, `$absent` when not sent), `expect.opened` (the URL handed to the system browser), `expect.signedIn` and `expect.pendingAfter` (the keychain and the sign-in after the request).

Runners: `scripts/m4-api-tests/runtime-http-contract.test.ts` here (node and vercel surfaces, in process); the desktop host [`buildytech/buildychat-desktop`](https://github.com/buildytech/buildychat-desktop) embeds this directory from its pinned `third_party/chat` submodule and runs the `desktop` surface with Go `httptest`. Encoded WebP bytes are never compared, only sizes, qualities and the grade.
