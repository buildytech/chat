0003/0004 extend 0001 (surfaces + agent channel); they do not replace Page Store ports or SLSA.
0005 records a historical ContextlY gate scheme for future design only; it does not implement lexproto or change runtime defaults.
0006 removes the WordPress runtime from this repo and makes mock ChatCore the default start; optional Session HTTP stays non-default.
0007 records the product-level three-host strategy (WordPress builder page, Browser, Desktop Wails3) on one pinned Stock catalog. Browser first; Wails3 later, same core. Portable export / WP import / round-trip tests are planned, not implemented. 0006 still bans a WordPress runtime in this repository. Plan: [docs/plans/one-buildy-three-hosts.md](../../docs/plans/one-buildy-three-hosts.md).
0008 makes registry.buildy.tw/svelte the only source of UI: a pinned CLI snapshot (`registry/svelte`, sha256 lock), published variants, `lib` without components, a "not in the registry" stub instead of own layouts, and a ZIP identical to `ui8kit init` + `add`.
0009 records that brands (badge + filter) live in the CodeGen-X database, not as per-brand kits or author namespaces/URLs. Contribution is closed and trusted, through XGenBot and the generator; `registry.buildy.tw` publishes one cleaned `@ui8kit` registry, with brand visible as metadata. Chat and WP FastY Builder both snapshot that registry. Catalog data for WordPress, a CLI snapshot for the plugin, and the brand field remain open (WordPress to be discussed further).
0010 pins registry.buildy.tw/props/v0.json (sha256 = sidecar = manifest, digest recomputed) and makes it the program gate: render props are the schema-filled merge of variant preset and page content, validated with Ajv 2020 (strict) for propose_layout, page-patch and the browser gate; errors list the schema's allowed values; no chat-side icon list. Fail-closed; lazy chunk in the browser.
0011 adds an explicit Ask / Build toggle in the composer (kept per chat; no intent word lists). Ask offers only read-only tools (`search_catalog`, `get_block`), answers in text (safe Markdown) with catalog block cards and never changes the page; Build runs with `tool_choice: auto`, so a text-only answer creates no proposal. Apply variant on an Ask card makes an ordinary pending set_variant proposal. Tool definitions live once in `packages/builder-core/src/agent/agent-tools.v1.json` (name, description, JSON Schema parameters, modes) for the chat runtime and later the WordPress builder.
0012 replaces the three catalog scripts with one `npm run snapshot` over one config (`catalog/snapshot.config.json`): the real CLI step, every Stock and registry input sha256-pinned and cross-checked, one graph `catalog/stock-registry.v0.json` (12 entity types, 14 edge types, every edge resolved, every variant preset validated with Ajv 2020), a computed `catalog/coverage.json`, one declared BuildY policy (`catalog/policy.v0.json`), the runtime `snapshot.json` / `search-index.json` derived from the graph and an offline `npm run snapshot:check`. Enrichment happens in codegen-x and the registry, never in the chat.
0013 renders Stock blocks by the screen's own composition (`layout` from the graph: order, variant, region): the Page DTO kind is the slot shape and `catalogBlock` decides what renders, so several list sections (logos, testimonials, pricing, faq, team, steps, proof, quotes, videos -> `features`) render side by side; no invented rows (empty states); `screenSupport()` is strict (every block renders) and dropped blocks are named.
0014 adds the Build inspector: blocks carry `data-block-id`, editor chrome (hover / selection outline, label) is drawn by the chat over the frame and never in the page (none in clean mode or `/preview`), the block tree is mounted in Build, fields come only from the pinned props schemas with registry widgets, writes go to the page-spec origin of a field through `parsePageSpec` + the props gate (rejections show the pointer and allowed values), only the changed block re-renders, typing is one undo step, and block operations (variant, reset, move, duplicate, remove) run through page-patch gates.
0015 puts every browser value under `buildy:v1:*` with an idempotent one-time migration, validates stored chats and page records against `session.schema.json` / page-spec at load (failures go to `buildy:v1:quarantine`, never dropped), adds the portable session file buildy:v1 (`window.buildy.export()` / `import()`, schema + program checks, Lab-readable, no credentials) and counts one page revision per committed change (coalesced typing = one revision = one undo step) with `session.pageRevision` and its history kept in sync.
0016 ships skins as registry items `theme-<skin>` (`registry:theme`, `npx ui8kit add theme-<skin>`, CLI 3.5.0): the chat's skin is session `skin` (session 1.1.0), switched in the preview header, applied to the preview document only, and exported 1:1 with the CLI install (theme files, lock entries, import after the styles entry, `data-skin` on `<html>`).
0017 makes the chat a compact IDE: nav | chat | preview | inspector, every side pane resizable (WAI-ARIA splitter: drag, arrows 8/32px, Home/End, Enter or double click resets) and collapsible to a 48px rail, Ctrl+B chat, Ctrl+I inspector, Ctrl+\ focus; one inspector column with Layers over Properties (not tabs, not two columns); the preview keeps at least 360px; columns from 1024px, inspector sheet below 768px; sizes and states in `buildy:v1:prefs` and optional session `prefs.layout` (session 1.2.0); density from h-10 bars, sm controls and text-xs on the 8+4 grid.
0018 makes Build self-correcting: `search_catalog` never dead-ends (relaxed facets, facet tree with counts, `browse`), rejections name the caller's block with the allowed values (`fix`), the same block error twice or a budget spent on a rejected page accepts the page without that block's choice (said in warnings), every reply carries the step budget and a failed run names the nearest screens; the Stock search box uses the catalog text index. Ask handoff is next.
0019 opens Stock collections (Open in BuildY, `buildy-collection:v1`): `/?collection=` or `/build?collection=` (read once, removed from the URL) or an imported collection file opens a new Build chat with removable chips and a note for skipped items (session 1.3.0 `collection`); the runtime recomputes allowed and required blocks from its own snapshot, `propose_layout` rejects `outside_collection` / `collection_item_unused` with the allowed list, and the ADR 0018 repair prunes blocks outside the set, never substituting.
0020 turns Ask recommendations into a checked page plan (`propose_plan`, page-patch ops validated on the current page, invalid ops shown with allowed values) that the author runs with Apply in Build, without a model call and with per-op results (session 1.4.0 `message.plan`); Build stays a pure assembler (no phrase recognition); both modes see a compact page directory and the hand edits since the last model turn; blocks resolve by title or catalog title (Logo cloud = `block.logos`); `propose_layout` cannot re-assemble the current page; reply text is generated from the actual change.
0021 adds field-level selection: codegen-x generates `data-slot` on every block root and list row (no `data-testid`, no `data-prop`) and a per-item `viewMap` in the registry props index; builder-core `view-map.ts` resolves a prop pointer to a preview element and back, a preview click focuses the field's inspector input and inspector focus outlines the field in the preview (`canvas.field`, `CanvasOverlay`), while the exported code stays 1:1 with `npx ui8kit add` (adopts the codegen-x ce2a9b90 registry, ADR 0012).
0022 pre-places a Stock collection page before the model (collection intake draft: the collection's screen or a renderable one, required items with their variants, removed kinds, allowed variants per block), runs the first collection turn compact (draft, collection catalog sources only, one tool, 3 steps), repairs collection rejections at once and keeps ADR 0018 (invalid variant: allowed list once, then the default; never stuck). ADR 0020 addendum: plan ops that change nothing are "keep" rows (`no_change`), not errors.
0023 fixes collection intake copy: catalog placeholders found by comparison with the host draft (no word lists) and said, an intake `propose_layout` schema narrowed to the draft with visible copy and rows required (one step, about 4.5k tokens, 0 of 8 live pages with placeholders vs 7 of 7 before), invented years stripped on every model block, near-miss Lucide icons mapped and the rest dropped before the gate (no repair round); and adds `replace {blockId, catalogBlock, variant?}` to Ask plans (another catalog block of the same kind, text carried by the props mapping, dropped fields named, Apply in Build without a model call; page-spec 1.2.0, session 1.5.0).
0024 makes Build agent-free capable (step A of 4): two areas, a left panel with Blocks / Sections / Chat tabs (panels stay mounted) and the preview, the inspector a slide-over on the preview instead of a third column; one Stock search `stockSearch` with the `stock-search/v1` result (q, type, role, spec, site, variant, scope, page; facet counts; absolute thumbnail and asset page URLs) used by both the home Stock field and the Blocks feed and ready for REST / MCP / CLI; 8 cards per page in one or two columns (`buildy:v1:feed`); "+" is an inspector `add` op (Stock sample of the variant for the page's screen family, after the selected section or at the end, every gate, one undo step, no model call); no contract change. Step B: the Sections tab is a sortable list (drag handle, up / down, Alt+Arrow with live announcements; remove; variant) of inspector ops, selection shared with the preview; screen cards start a page with `stockScreenDraft` (the intake's program propose_layout, no model call); stock-search/v1 items carry `supported`. Step C: block cards drag into the preview (a host drop layer over the iframe draws the insertion line, scrolls the frame, drops through the inspector `add` op with `at`) or onto the Sections list (the tab opens on hover); `addSlotCheck` keeps content between header and footer; refused cards and slots show the reason. Step D: the inspector is a non-modal 320px slide-over on the preview (opens on a preview or Sections pick with the field focused, Esc / close, remembered; column and Layers tree removed); moves follow the add position rules (`moveSlotCheck`); Sections drops show "Insert at position N". Empty start: Build opens on Blocks; the first "+" or drop on a chat with no page starts an empty page on a default Stock screen (`emptyPageStart`, chosen by the block kind) and adds the block as one undo step, no model call; header and footer are optional (a page may start with Hero), the position rules apply only to one that is there; Stock cards share a full-bleed thumbnail frame (`StockMediaCard`) and the home Stock screens use the feed card in 2 columns.
0025 adds Settings > Theme import: one theme as the Stock theme editor (codegen-x/ui8kit app.codegen-x.com) exports it, format magazine-theme v2, checked by the ported Stock schema and reader (strict, issues with JSON Pointer and allowed values); the one Custom Skin slot (`buildy:v1:customSkin`) shows as "Custom Skin" in the preview skin selector, renders on the preview document only as Stock renders it (base skin `theme-<skin>`, root attributes and inline variables, fixed mode, fonts, Stock base rules), exports in the ZIP (index.html, `src/custom-skin.css`, `theme.json`) and round-trips byte for byte; the Settings region is compact and scrolls on its own.
0026 adds the chat UI skin (the shell only, never the preview): a tonal dark and light ladder in `styles/chat-skin.css` mapped onto the kit's shadcn names, hairline edges instead of outlines (text field edges and focus rings kept at 3:1), concentric radii on the 8+4 grid (controls 8, cards and rows 12, dialogs 16, pills full), shadows only on floating layers, 1.5-stroke monochrome icons, 4px scrollbars, secondary row actions on hover / focus, and Settings > Theme System / Dark / Light (`buildy:v1:themePref`, default System).
0027 makes the screen family advisory: it never rejects a block (hard rules only: header first, footer last, a renderer, schemas), it is derived from the composition after every operation (majority of telling sections, else generic), ranks the Blocks feed, can be pinned in Sections, and each change is its own undo step (`set_family`, page-spec 1.4.0 `provenance.family` / `familyPinned`, session 1.7.0). Feed availability is computed per card from the item and the page; a screen with any renderable section starts a page or drops its sections into one, on every result page.
0028 extends the theme-only scope of 0026 into a UI8Kit app-composition refactor: layered typography, one composer surface, coherent first-use and conversation hierarchy, purposeful borders and consistent shell controls. Compact density, the 0024 inspector slide-over, accessibility floors and preview/export isolation remain; implementation and visual acceptance are pending. See the [SLO](../slo/chat-ui-refinement.md) and [plan](../../docs/plans/chat-ui-refinement.md).
