# ADR 0008: The UI8Kit registry is the single source of UI

- Status: Accepted
- Date: 2026-11-09
- Extends: [0003](0003-creator-surfaces-preview-code.md) (Preview / Code), [0007](0007-one-buildy-three-hosts.md) (one pinned Stock catalog)
- Closes: chaosbun#144 (sync with the rebuilt registry); uses the published variants of chaosbun#137

## Context

The chat used to carry its own copies of UI: hand-written primitives (`src/ui`, `src/lib/compose`), its own colour
tokens, a vendored subset of registry files (`src/registry`, `pack-kit.json`), a per-kind "generic" renderer that drew
blocks the registry did not cover, and variant presets generated from compose-gen specs. Every copy drifted from
`registry.buildy.tw/svelte`, and the exported ZIP was not what `npx ui8kit` produces.

## Decision

1. **One source.** Every UI component, block, style token and utility comes from `https://registry.buildy.tw/svelte`.
   The chat pins a snapshot: `registry/svelte/` is the literal output of `npx ui8kit@<cli> init --yes --framework svelte`
   followed by `npx ui8kit add --all` in a clean project with the CLI default config (`dir: src`). It is generated by
   `npm run registry:snapshot` and never edited by hand. `registry/svelte/ui8kit.lock.json` (sha256 per file) is the
   lock; `npm run registry:check` (offline) verifies every file against it.
2. **Variants.** `registry/variants.v0.json` is the pinned copy of `https://registry.buildy.tw/variants/v0.json`
   (verified against its `.sha256`). It links every Stock catalog asset (`block.x/variant`) to a registry block and
   its props. Render props = merge(type defaults, variant props, page content); dictionary refs (`{"$": "ui.*"}`) are
   dropped so the page content fills them. Since [0010](0010-props-schemas-program-gate.md) the defaults, prop kinds
   and validation come from the pinned published props schemas (`registry/props.v0.json`), not from the TS types. `packages/builder-core/src/catalog/sources.json` is derived from the
   snapshot and the variants (`npm run registry:sources`); `registry:check` fails when it is stale.
3. **`lib` is logic only.** `apps/chat-web/src/lib` holds TypeScript (stores, page store, agent, i18n, editor code) and
   no `.svelte` component; a test enforces it. App UI lives in `apps/chat-web/src/app` and is composed only from
   registry components (`$registry/...`). The chat declares no colour tokens; the Istok font is the only brand override.
4. **No own layout for blocks.** Preview renders each page block with its registry block. A block whose catalog
   asset has no registry item renders an explicit "Not in the registry" stub (the registry `Alert`), never a
   chat-made layout. The stub count is part of the acceptance checks.
5. **Export = CLI.** The ZIP has `ui8kit.config.json`, `ui8kit.lock.json` (the lock restricted to the page's items and
   the init items) and the registry files under `src/` byte-for-byte as `init` + `add <items>` write them, plus the
   page files (`src/App.svelte`, `src/sections/*`, `src/main.ts`, `index.html`, `package.json`, `vite.config.ts`,
   `README.md`, `page.json`, `GENERATOR.json`, `manifest.json`). It builds with `npm i && npm run build`.
6. **Naming.** Chat paths use registry names (`blocks`, `components`, `kit`, `utils`); the chat has no `compose` path
   of its own. `compose/` exists only inside the generated tree because the registry installs there.

## Consequences

- Updating UI means re-running `registry:snapshot` against a newer registry / CLI, not editing chat code.
- Gaps of the registry or CLI are reported upstream (chaosbun, ui8kit/cli) rather than patched in the chat.
- Child-level selection inside a block is not available: registry blocks own their inner markup.
- The browser bundle carries the catalog sources (item graph, variants, props) for the ZIP export.
