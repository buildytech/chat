## Corrections (2026-11-16, after owner review; verified on live docs.x.ai)
- Prompt caching key: Chat Completions uses HTTP header `x-grok-conv-id` (guides: https://docs.x.ai/developers/advanced-api-usage/prompt-caching/maximizing-cache-hits); body `prompt_cache_key` exists in the Chat Completions REST ref but is "Plumbed to x-grok-conv-id". Responses API uses body `prompt_cache_key`. Pick one documented mechanism. Caching is best-effort (eviction); compare compact context vs stable cacheable prefix, not "cache is the main lever".
- Streaming function calls: "the function call is returned in whole in a single chunk" (https://docs.x.ai/developers/tools/function-calling). Earlier claim of incremental tool_calls was WRONG; UI progress needs a runtime->browser event protocol.
- Zero/missing usage is NOT an error and does not justify a paid retry. Unknown cost must be recorded as unknown, not 0. Chat Completions `message.content` is `string | null`; null with tool_calls is normal; array content in responses is Responses API only. Retry only 429/5xx with bounded backoff within budget (https://docs.x.ai/developers/model-capabilities/text/best-practices).
- Streaming usage (Chat Completions): needs `stream_options.include_usage: true`; cost only in final chunk. Responses ref: `cost_in_usd_ticks` is `integer | null`.
- `max_completion_tokens` limits visible text, not reasoning/function calls: time control needs deadline + AbortSignal; project limits are Vercel 300 s / internal 285 s, not xAI's 900 s.
- `parallel_tool_calls:false` limits reads too; keep host-side single-write check.
- Grok 4.7 `low` re-test: measure time and quality, no auto model switch.
- Doc fetching: `.md` suffix URLs now 404; fetch canonical URLs with `Accept: text/markdown`. `/docs/guides/*` redirect to `/developers/*`.
